# LandOS Learning Guide: Geometry Normalization Engine (Phase P2.6.3)

**Learning Objective:** Understand why LandOS uses a Geometry Normalization Engine to process `RAW_VECTOR_PRIMITIVES` artifacts into `NORMALIZED_VECTOR_PRIMITIVES` without re-reading source files, how duplicate removal, line segment merging, polygon gap repair, and centroid math operate deterministically, and how this stage establishes a permanent contract for all downstream CLM spatial analysis engines.

---

## 1. Request Lifecycle & Modular Pipeline Position

```
Upload ──► Inspection ──► PDF Reader ──► Vector Extraction (RAW_VECTOR_PRIMITIVES)
                                                  │
                                                  ▼
                                   Geometry Normalization Engine
                                                  │
                                                  ▼
                                    NORMALIZED_VECTOR_PRIMITIVES
                                                  │
                                                  ▼
                                     Canonical Layout Model (CLM)
```

### The Compiler & GIS Analogy:
- **Compiler Analogy:** Raw vector primitives are like raw syntax tokens emitted by a lexer (`int`, `x`, `=`, `5`, `;`). The Geometry Normalization Engine cleans up redundant tokens, merges statements, and standardizes structure before AST construction.
- **GIS Analogy:** CAD exports contain overlapping line segments, floating point precision noise ($10.0000000001$), disconnected street segments, and nearly-closed polygon loops ($1.5\,\text{pt}$ gap). Normalization cleanses and repairs geometry so spatial R-Tree indexers and polygon detectors receive clean topology.

---

## 2. The 6 Sub-Components of GeometryNormalizer

1. **`CoordinateNormalizer`:** Rounds floating point coordinates to 2 decimal places and removes consecutive identical vertices.
2. **`DuplicateRemover`:** Uses direction-invariant canonical string keys (`canonical_key`) to detect and remove identical line/polygon primitives or reversed line directions.
3. **`SegmentMerger`:** Identifies line primitives whose endpoints touch ($\le 0.5\,\text{pt}$ tolerance) and merges them into continuous polylines (`POLYLINE`).
4. **`PolygonRepair`:** Detects non-closed polylines where start and end points are close ($\le 2.0\,\text{pt}$ gap) and closes them into `CLOSED_POLYGON` primitives.
5. **`BoundingBoxCalculator`:** Computes `minX`, `minY`, `maxX`, `maxY`, `width`, `height`, `area`, and center `(centerX, centerY)`.
6. **`StatisticsBuilder`:** Computes length, perimeter, centroid, orientation angle (degrees), aspect ratio, primitive counts, duplicate removals, merged segments, and repaired polygons.
